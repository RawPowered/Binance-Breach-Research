# Attribution verification plan

**Status: proposed checks, not completed transaction reproduction.** No raw transaction ledger is published as verified by this project.

## 1. Reconstruct the financial connection

Start with [BitOK's shared-recipient claim](https://bitok.org/blog/binance-hack-bitok-investigation). Collect every source transaction, protocol deposit, cross-chain correspondence and destination payout. Record chain, hash, block, UTC time, asset, quantity, destination and the source of each ownership label. Retain the distinction between direct transaction facts and analyst labels.

Check the reported eight-versus-five payout grouping, amounts and observation cutoff against independent data sources. Resolve protocol fees, aggregation and timing before using amount similarity as a correspondence. Preserve retrieval dates and raw-response hashes. Unavailable data should remain an explicit gap.

## 2. Test ownership and operational roles

Determine whether the recipient is a private wallet, custodian, swap provider or pooled service. Investigate onward control and whether observed activity can distinguish an intruder from a laundering provider. A deposit alone is insufficient to assign the sender's identity to the recipient or vice versa.

## 3. Audit the inherited actor labels

Trace every prior-incident label to its earliest accessible evidence and publication date. Review the Bitget attribution as its own claim, using [Elliptic's qualified account](https://www.elliptic.co/insights/bitget-attack-pushes-suspected-north-korea-crypto-heists-over-1-billion-in-2026/). Keep shared observations and citations connected in the [dependency map](source-dependencies.csv). Do not turn multiple publications of one finding into a numerical confidence score.

## 4. Seek independent identity and state-affiliation evidence

Document any public forensic or investigative material connecting wallet control to identifiable operators, and those operators to the state. Evaluate source authenticity, collection scope, alternative explanations and what is withheld. Historical attribution to the same group is context; it does not establish participation in this incident by itself.

## Reporting rules

Use separate statuses for source statement reviewed, publisher-reported finding, independently reproduced transaction relationship, operator identity and state affiliation. Record which checks were performed, by whom, with which data and what limitations. An official attribution remains official even when its full basis is not public; this project must separately state its own verification level.
